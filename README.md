# panzir

Linux-приложение «сейф»: именованные LUKS2-хранилища (файл-контейнер или USB)
через udisks2 по D-Bus, без собственного привилегированного кода. Правила
проекта и инварианты — в `CLAUDE.md`.

## Главное окно

![Список хранилищ: состояние, основные действия и подробности](docs/assets/ui-redesign.png)

На карточке сразу видны состояние и «Открыть»/«Закрыть». «Подробнее» раскрывает
путь контейнера, SSH-подключения, переименование и удаление записи.
Форма создания имеет постоянные подписи и доступные при прокрутке кнопки.
Корень нового файлового хранилища принадлежит создавшему его пользователю
и имеет права 0700: файлы можно записывать сразу после создания.
Ошибки остаются у соответствующего хранилища до скрытия или новой попытки.
На снимке показаны тестовые записи. Работа с носителями пока не поддерживается.

## SSH-связка

Хранилище можно связать с SSH: на карточке хранилища добавляются хосты
(имя, адрес, логин, необязательный порт, относительный путь ключа внутри
хранилища, например `ssh/id_ed25519`),
и по явному подтверждению — с показом точной строки — в начало вашего
`~/.ssh/config` вставляется `Include` на сгенерированный сниппет
`~/.config/panzir/ssh-<метка>.conf`. Контракт:

- **Открытое хранилище** — `ssh <имя>` работает: ключ ищется через симлинк
  `~/panzir-<метка>`, с `IdentitiesOnly yes`, `IdentityAgent none` и
  `PreferredAuthentications publickey`. Ключ читается из контейнера;
  агент и вход по паролю для этих хостов отключены.
- **Закрытое хранилище** — соединение падает по аутентификации: путь ключа
  указывает в мёртвый симлинк, даже если у вас есть другой ключ к тому же
  хосту. Строка `Include` и сниппет при закрытии остаются — это штатно.

Сверка через `ssh -G` подтверждает единственный ожидаемый путь ключа и эту
политику. Дополнительный `IdentityFile` в другом блоке считается конфликтом:
OpenSSH складывает явно указанные ключи, даже если наш `Include` стоит первым.
Закрытие хранилища ограничивает новую аутентификацию; уже установленные
SSH-сессии и соединения `ControlMaster` оно не разрывает.

Ваш `~/.ssh/config` не редактируется молча: вставка и починка («поднять
строку первой», если вы сдвинули её руками) — только по подтверждению,
остальное содержимое и права файла сохраняются.
