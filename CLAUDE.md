# panzir — правила проекта

Linux-приложение «сейф»: именованные LUKS2-хранилища (файл-контейнер или USB) через
**udisks2 по D-Bus**, без собственного привилегированного кода. Целевая система — Fedora
Workstation; расширение по Linux (Ubuntu/Debian, Arch) — после MVP. macOS и Windows вне
области: там нет ни LUKS, ни udisks2, и эквивалент требовал бы собственного
привилегированного хелпера — ровно того, чего проект избегает.

## Структура

```
crates/core/   вся логика без GUI
crates/gui/    eframe/egui — главное окно (PR-3b); остальные экраны в работе
scripts/       run-it-tests.sh — живые интеграционные тесты
```

**Модули-владельцы `crates/core` — правка идёт к владельцу вопроса, а не туда, где удобно:**

| Модуль | Владеет |
|---|---|
| `udisks.rs` | **единственный**, кто говорит с udisks2 по D-Bus, и правда о loop-устройствах из sysfs |
| `create.rs` | одноразовое событие: создание контейнера |
| `lifecycle.rs` | повторяемые операции: открыть / закрыть / узнать состояние существующего хранилища |
| `vault.rs` | модель и машина состояний, без ввода-вывода |
| `registry.rs` | `vaults.toml`: чтение/запись под advisory-локом, 0600, без секретов |
| `keyslot.rs`, `header.rs` | вызовы `cryptsetup` (второй пароль, бэкап заголовка, проверка фразы) |
| `mountpoint.rs` | симлинки `~/panzir-<метка>` |
| `deps.rs` | проверка окружения при старте |
| `error.rs` | все варианты ошибок |

**Модули-владельцы `crates/gui`:**

| Модуль | Владеет |
|---|---|
| `main.rs` | **единственная** встреча с системой: `run_native`, подписчик журнала, чтение окружения и `Registry::default_path()` — по одному разу каждое |
| `app.rs` | связь «окно ↔ ядро»: рантайм, фоновые задачи, состояние, перевод отказов ядра на человеческий язык. Экраны асинхронности не знают |
| `view_list.rs` | экран 1: список хранилищ, управление записями, плашка окружения |

## Гейты — дословно, с флагами

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings   # без --all-targets тесты не проверяются
cargo test --workspace
cargo deny check advisories
cargo deny check licenses bans sources
cargo build --release --workspace
```

Зелёный гейт — это прогон **после последней правки**. Тронул файл после прогона — гейт
недействителен.

## Живые интеграционные тесты

Помечены `#[ignore]` с причиной: они требуют работающего udisks2, polkit и активной
локальной сессии. Запуск — **только** через `scripts/run-it-tests.sh`: он ставит временное
polkit-правило, отключает автомонтирование рабочего стола, свипает за собой в `trap EXIT` и
возвращает среду. Необязательный аргумент — фильтр имени теста (нужен для мутационных прогонов).

Запуск сьютов напрямую при включённом автомонтировании оставляет зомби-тома — так уже было.

**Правила тестов:**
- каждый живой тест берёт `UDISKS_LOCK`: демон не переживает конкурентные вызовы;
- имена контейнеров — `panzir-t<N>.vault`: по ним свип отличает наши от настоящих хранилищ;
- у каждого теста RAII-уборка: упавшая проверка не должна оставлять том живым;
- новый тест обязан сначала **упасть** на сломанном коде — тест, который никогда не падал,
  не отличает рабочий код от сломанного.

## Инварианты, которые нельзя ломать

1. **Закрытие хранилища не удаляет файл контейнера.** `teardown_file_container` удаляет — это
   уборка тестов, не продуктовая операция.
2. **Снять loop-устройство ≠ закрыть том.** `Loop.Delete` отвечает `Ok`, пока живая dm-crypt
   держит устройства. Правильный путь — `close_encrypted` (autoclear → unmount → lock).
3. **Второй loop на один контейнер — порча данных** (две dm-crypt поверх одного LUKS). Перед
   подъёмом устройства проверяется, не подключён ли файл уже.
4. **Опции монтирования проверяются по результату** (`findmnt`, заголовок LUKS), а не по тому,
   что вызов не вернул ошибку: udisks2 молча игнорирует неизвестные опции.
5. **Секреты не попадают в argv, окружение и логи** — только через stdin или D-Bus.
6. `unsafe_code = "forbid"`; `unwrap`/`expect` — только в тестах.
7. **Прямая зависимость `winit` в `crates/gui` — не «неиспользуемая».** Вызовов у неё нет: она
   выбирает декорации окна без шрифтового парсера (`wayland-csd-adwaita-notitle`). Удалить —
   вернуть в граф `ttf-parser` и вместе с ним RUSTSEC-2026-0192, у которого нет безопасного
   обновления, то есть красный гейт Security Audit.
8. **Фоновые задачи заводятся ТОЛЬКО через `App::spawn_waking`.** Окно реактивное: без
   `request_repaint()` из завершившейся задачи результат никто не покажет — после клика окно стоит
   с неактивными кнопками до случайного события ввода. Вводя любой асинхронный ответ, письменно
   ответь: **кто разбудит окно**.
9. **Путь реестра и значения из окружения приходят в `App` параметрами, а не читаются внутри.**
   Иначе тесту нечем подставить своё: `std::env::set_var` в edition 2024 — unsafe-функция, а
   инвариант 6 её не пустит. Разбор значений — чистые функции от строки.
10. **Отказ ядра не проглатывается.** Каждый `Err` доходит до человека через единственный перевод
    в `app.rs` (`match` без ветки `_`, чтобы новый вариант ошибки ломал сборку). Тихий `return`
    вместо сообщения — тот же дефект, что молчание.

## Состояние сессии

`.claude/HANDOFF.md` — снимок состояния для следующей сессии: где стоим, что дальше, чего не
трогать. В git не коммитится — это состояние машины, а не история; история живёт в спеках и
сообщениях коммитов. Во frontmatter — снимки `HEAD` и статуса рабочего дерева, снятые командами:
по ним следующая сессия проверяет, не протух ли файл, и при расхождении не доверяет ему.
